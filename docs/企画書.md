# SQL Reflex（仮）企画・実装仕様

## 1. 概要

ブラウザ上でSQLを高速に反復練習するWebアプリ。

SQL初心者に文法を教える教材ではなく、

> SQLの知識はあるが、JOIN、GROUP BY、サブクエリ等を考えずに手癖で書けるレベルまで反復したい人

を対象とする。

「問題を読む → SQLを書く → 実行 → 正誤確認 → 次の問題」

を可能な限り高速に繰り返せることを最重要視する。

---

# 2. コンセプト

SQL版のタイピングゲーム / ドリル。

重視するもの：

- 説明を読む時間ではなく、SQLを書く時間
- キーボード中心の操作
- 即時実行
- 即時採点
- 大量の問題を高速に回せる
- 正解SQLとの文字列比較ではなく、実行結果で採点する
- 実際のSQLiteにSQLを投げる

重視しないもの：

- SQL入門講座
- 長文の解説
- 動画教材
- アカウント管理
- サーバーサイドDB
- ランキング等の競技機能

# 5. DBの扱い

## 重要方針

**問題用DBを永続化しない。**

OPFSは使用しない。

SQLiteの `:memory:` DBを利用する。

各SQL実行時：

```text
Run
 ↓
新しい :memory: DBを生成
 ↓
schema.sql
 ↓
seed.sql
 ↓
ユーザーSQL
 ↓
採点
 ↓
DB破棄
```

したがってユーザーが、

```sql
UPDATE users ...
DELETE FROM orders;
DROP TABLE users;
```

などを実行しても問題ない。

次回実行時には必ず初期状態へ戻る。

### 理由

同じDBを使い回すと、

```sql
UPDATE users ...
```

を一度実行したあと、SQLを書き直して再実行した際に前回の変更が残り、問題の再現性がなくなる。

したがって**Run単位でDBを初期化する**。

# 6. Dataset

複数問題から共有可能なDatasetを定義する。

例：

```text
datasets/
  ecommerce/
    schema.sql
    seed.sql

  company/
    schema.sql
    seed.sql

  sns/
    schema.sql
    seed.sql
```

例：

```sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL
);

CREATE TABLE orders (
  id INTEGER PRIMARY KEY,
  user_id INTEGER NOT NULL,
  amount INTEGER NOT NULL,
  ordered_at TEXT NOT NULL
);
```

seed.sql：

```sql
INSERT INTO users ...
INSERT INTO orders ...
```

MVPではSQLファイルをDB初期化時に実行すればよい。

データ量が増えて初期化コストが問題になった場合は、事前生成したSQLite DBをWASMメモリへdeserializeする方式へ変更可能。

SQLite WASMはSQLite DBのバイト列をインメモリDBへロードする仕組みを公式に提供している。

# 7. 問題定義

問題はコードではなくデータとして追加できるようにする。

例：

```ts
type Exercise = {
  id: string
  title: string
  prompt: string

  datasetId: string

  difficulty: 1 | 2 | 3 | 4 | 5

  tags: string[]

  type: "query" | "mutation"

  solutionSql?: string

  verifySql?: string

  orderMatters?: boolean

  hints?: string[]
}
```

例：

```ts
{
  id: "join-001",

  title: "注文したユーザー",

  prompt:
    "注文履歴が存在するユーザーの名前と注文金額を取得してください。",

  datasetId: "ecommerce",

  difficulty: 1,

  tags: ["JOIN"],

  type: "query",

  solutionSql: `
    SELECT users.name, orders.amount
    FROM users
    JOIN orders
      ON users.id = orders.user_id
  `,

  orderMatters: false
}
```

# 8. 採点

## SQL文字列比較は禁止

以下はどちらも正解になり得る。

```sql
SELECT u.name
FROM users u
JOIN orders o ON ...
```

```sql
SELECT users.name
FROM users
INNER JOIN orders ON ...
```

したがってSQLそのものは比較しない。

---

## SELECT系

ユーザーSQLのResultSetと、solutionSqlのResultSetを比較する。

```text
ユーザーSQL
     ↓
practice DB
     ↓
ResultSet A

solutionSql
     ↓
reference DB
     ↓
ResultSet B

A == B
```

reference DBはユーザーから操作できない独立したDBとする。

### 比較

基本：

- カラム
- NULL
- 値
- 行

を比較する。

`orderMatters = false` の場合は行順を正規化して比較する。

`ORDER BY` 自体が問題の目的の場合は、

```ts
orderMatters: true
```

とする。

# 9. INSERT / UPDATE / DELETE問題

Mutation問題も実行可能にする。

例：

> id = 10 のユーザーのnameを "Alice" に変更してください。

ユーザー：

```sql
UPDATE users
SET name = 'Alice'
WHERE id = 10;
```

採点用SQL：

```sql
SELECT
  name = 'Alice'
FROM users
WHERE id = 10;
```

Exercise：

```ts
{
  type: "mutation",

  verifySql: `
    SELECT name = 'Alice'
    FROM users
    WHERE id = 10
  `
}
```

ユーザーSQL実行後にverifySqlを実行して判定する。

これにより、

- INSERT
- UPDATE
- DELETE

も練習可能。

# 10. Worker

SQLiteは専用Web Worker内で実行する。

目的：

- UIフリーズ防止
- 重いSQLからUIを隔離
- 暴走SQLをWorkerごと停止可能にする

通信イメージ：

```ts
type WorkerRequest =
  | {
      type: "execute"
      exerciseId: string
      sql: string
    }

type WorkerResponse =
  | {
      type: "result"
      columns: string[]
      rows: unknown[][]
      correct: boolean
      durationMs: number
    }
  | {
      type: "error"
      message: string
    }
```

SQLite WASM自体をWorker内部で初期化する。

旧Worker1 / Promiser APIには依存せず、通常のWeb WorkerからSQLite WASMを直接利用する。

---

# 11. 暴走対策

公開Webアプリなので最低限以下を入れる。

## Query Timeout

例：

```text
2秒
```

一定時間以上応答しない場合：

```text
Worker terminate
 ↓
Worker再生成
```

する。

SQL実行環境自体がWorkerなので、DBごと破棄して問題ない。

## Result制限

UIへ返すResultSetは最大500行程度に制限する。

大量SELECTによるブラウザ負荷を防止する。


# 21. 最重要設計原則

このアプリはSQL教材ではない。

**SQLをたくさん書くための道具である。**

したがって、新機能を検討するときは、

> それによってユーザーがSQLを書く回数・速度・継続率が上がるか

を判断基準とする。

説明、設定、画面遷移、演出がSQLを書くまでの摩擦になるなら削る。

最小ループは常に、

```text
Question
↓
Write SQL
↓
Run
↓
Correct / Incorrect
↓
Next
```

である。
